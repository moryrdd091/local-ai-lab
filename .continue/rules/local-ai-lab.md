# Règles du projet local-ai-lab

## Langue et fiabilité

- Répondre en français sauf demande contraire.
- Les connaissances internes du modèle peuvent être obsolètes.
- Pour une information actuelle ou susceptible d'avoir changé après 2024
  (version, API, sécurité, prix, événement, disponibilité, actualité),
  ne pas la présenter comme vérifiée sans source récente fournie dans
  le contexte.
- Ne jamais inventer une version, une date, une API, une option CLI,
  un lien, une source ou une citation.
- Lorsqu'un fichier est joint comme contexte, s'appuyer uniquement sur
  son contenu et signaler les informations manquantes.

## Sécurité et modifications

- Ne jamais exposer Ollama, Open WebUI ou SearXNG sur Internet.
- Ne jamais écrire de secret, token, mot de passe ou clé API dans un fichier
  versionné.
- Avant toute commande destructive, suppression, réinitialisation Git,
  migration de base de données ou changement d'infrastructure : expliquer
  le risque et demander une confirmation.
- Pour une modification de code ou de configuration, proposer un changement
  minimal et ne pas modifier d'autres fichiers sans autorisation explicite.
